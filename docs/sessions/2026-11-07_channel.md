## 6. Next pass: ladder templates in code (owner's choice, fourth check-in)
Goal: the six ladders and their twelve variations (canvas boards L1-L6 with b/c, matrix M1, tuner M2) become stored templates that generate a piece's next steps, tuned by the tuner's settings. A sketch to confirm with the owner before building:
1. **Template shape.** A step is an evolution type, a share type, an outlet, an offset (days from the first post or from the piece's date) and a branch point. Templates live as code or data in `packages/services/src/channel-ladders.ts` (or a table, if the owner wants them editable). The matrix board's nine-step "variation function" says how intensity, cadence, effort, reach and go-live generate a ladder; port that function.
2. **Generator in `load.ts`.** It replaces the fixed gap rules (share, quote card, film, write, letter) with the chosen template's steps for each piece, placed in routine slots or by date as now. Dismissed rows and `channel_rules` still apply.
3. **Choice per piece.** Each piece gets a default template by kind, and "Change ladder" is offered on the piece pop-up. A per-person or per-org default may be needed; ask.
4. **The tuner as settings:** the Routines page or the piece pop-up, from board M2.
5. Verify in the harness (add a page), type-check, then rebuild with the memory-cap steps.

Not started and still open:
- the dock's expander (board D2: when, star, snooze);
- a send worker for scheduled posts;
- quote-card pictures;
- follow-up lineage (a clip or writing linked back to its piece);
- network-wide library search;
- live booth for non-admins;
- per-person time zone;
- reading Instagram's real posting cap (Meta's documentation now says 50 or 100 a day, not 25);
- the duplicated authorization helpers (`lib/channel/actions.ts` and `packages/actions/src/server/channel.ts` must change together).
