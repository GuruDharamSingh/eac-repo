# Studio forms split: Quick-Form, Norm-Form, Deep-Form (2026-11-14)

Records the developer's decisions of 2026-11-14 (side discussion, relayed into the main session) on splitting the shared publishing forms into a small package for every site, plus four read-only surveys run the same evening: how `saveMeetingContent` differs from the seven per-app `saveContentAction` copies, how series are made and edited, how the two offering services relate, and where "meeting" and "gathering" are used. Nothing in the code has changed. The forms code belongs to the forms-body session ("Studio form design versioning", `local_6ba05738`), which should review this before any file moves. Related: `docs/open/publishing-forms-handoff/PLAN.md`, `docs/open/CHANNEL_ON_SITES_2026-11-12.md`, `docs/open/EDITING_LANDSCAPE_2026-11-12/HANDOVER_TEAM_2026-11-14.md` §1, `docs/open/NETWORK_SERVING_ARCHITECTURE_2026-11-08.md` §4.1.

## 1. Decisions (developer, 2026-11-14)

| Item | Decision |
|---|---|
| New package | `@elkdonis/studio-forms`, the small tier, installed on every site. |
| Tiers in it | **Quick-Form** (key fields; the Channel social-post quick sheet's style, `@elkdonis/channel/quick-spec`, with defaults filled from context: source piece, Channel suggestion, org and site) and **Norm-Form** (all standard data the platform needs). Every site gets both. |
| Norm-Form contents | tiptap body; cover crop and framing with preview (`CoverFramer`); a font choice; direct-edit available; the blocks editor (essay Canvas, `threads.body_doc`) as an optional choice for the What row. |
| Loading | tiptap and the blocks editor load only when Norm-Form or the What row opens (`next/dynamic` / `import()`). three, konva and Filerobot stay out of the package. |
| Deep-Form | the existing `@elkdonis/studio` on arts-collective, unchanged for now: shell, Queue and Board, Filerobot image editor, wordart, large font, colour and theme tools. |
| Getting to Deep-Form | a plain link on arts-collective.com, shell-served domains, and standalone apps mounted under an arts-collective.com path (as `/books`, `/astro`); the existing hand-off token from a site's own domain. |
| Saving | shared functions in `@elkdonis/services` with org checks; a thin server-action wrapper per site; no per-site copies. |
| Render (GPU server) | out of scope; no such server exists. |
| Form kind id | `meeting`, not `gathering`, also in what people see ("Meeting", "Next meeting"). No redirect from `?kind=gathering`: existing rows are seeded data. |
| Offering | `service` stays the kind id; "Offering" is the page and section name and the noun for one item; "Offer" is the verb. Service is meant broadly: any product or business offering of a person or org. |
| Series | stays its own thing, managed as series-site manages it today, not folded into the meeting form (developer, 2026-11-14 main session). |
| Recurrence | a series can take hand-picked, ordered dates as well as a regular rule. |

Parked, not now: booking as a full module that is also a section in any form that needs it; experiences (the artist always has their own offering; a curator or guide includes it as a stop under an agreement on a percentage or goal amount); events (one ticket for the main programme, other offerings in the space listed as extras); agreements as their own package with the platform as arbiter.

### 2.3 `saveMeetingContent` against the seven `saveContentAction` copies
Lineages, by `diff` changed-line counts: amrit-canada and elktours are functionally identical (24 lines, log prefixes and one comment); sunjay (+series guard, metadata merge) and innergathering (+audience/`min_role`, `showCycleBadge`) are small deltas of the same code; hidden-enneagram, ifac and arts-collective (`createThreadAction`) are separate code.

What a copy does that `saveMeetingContent` (`packages/services/src/meeting-content.ts`) does not:
1. **`min_role` and audience are not written.** `visibility` falls back to `'PUBLIC'` when the caller omits it (`meeting-content.ts:374`); `min_role` is only read, for the Talk room (`:409-424`). innergathering's copy writes both (`apps/innergathering/src/lib/cms/actions.ts:174-240`). Moving innergathering (private by default) to the shared save without this would publish members-only meetings.
2. Kinds: it saves `meeting` and `event` only and refuses series on edit (`:510`). Posts (every copy), `service` (hidden-enneagram), workshops with sessions (arts-collective) and series creation (ifac `createSeries`) have no shared save.
3. `revalidatePath`: none in the service (no Next dependency), and its caller `meeting-actions.ts` does not revalidate either (verified by grep). The copies revalidate `/`, `/manage` and the feed paths.
4. `attachMaterials` (media rows) in amrit-canada, elktours, sunjay, innergathering.
5. `showCycleBadge` (innergathering); pen-name or org byline (`resolveActor`, arts-collective); feed required (the copies) vs optional `section` (shared).
6. Permission differs: the shared save lets an author edit their own row and lets `is_admin` create; the org-site copies allow owner and guide only (ifac also lets members post).
7. Slug: the copies re-derive the slug from the title on each save; the shared save keeps the original. A choice to make, not necessarily a gap.

Only in `saveMeetingContent`: `body_doc` storage with `renderEssayHtml` → `sanitizeRichText`; the review rule `statusForNewThread` and the autosave-only-over-drafts guard; the audience-aware Talk room policy from `9f14ec69` (no copy received it); input validation (dates, duration, limits, URL schemes, time zone, reminder range); `reminder_minutes_before` (no copy writes it, so only shared-save meetings can get attendee reminders, per `attendee-reminders.ts:94`, assumed on the reader side); rota hosts and the calendar mirror (ifac's copy also has both).

Drift between the copies, independent of the split:
- hidden-enneagram and arts-collective call no sanitiser in their save (verified by grep in both `lib/cms/actions.ts`; the read side was not checked).
- amrit-canada, elktours and hidden-enneagram replace `metadata` (`apps/amrit-canada/src/lib/cms/actions.ts:219`), dropping keys other writers set; sunjay, innergathering and ifac merge.
- Talk rooms are created `public` and listable whatever the visibility in the org-site copies (`apps/innergathering/src/lib/cms/actions.ts:101`), including on innergathering.
- Only sunjay and ifac guard against saving over a series.
- hidden-enneagram hard-deletes threads; the others archive.

### 2.4 Series
- ifac and sunjay create and edit series through `packages/series-site`: planner "+ New series" (`routes/hubNewSeries.ts:96-141`), editing only in the planner (`/hub/series/<id>#settings`), cancel and move per week (`packages/services/src/meeting-series.ts`, `moveSeriesSession` ~:1726, `saveSeriesSchedule` ~:2040). The planner surface is `cms-ui/hub/SeriesPlannerSurface.tsx` and has no arts-collective dependency.
- The Studio form treats series as a variant of the gathering form (`forms.repeat_as_series`, `rules/answers.ts:151`). PLAN records this as "'series' is derived, never chosen" (`docs/open/publishing-forms-handoff/PLAN.md:165`). Its save, `createSeriesFromForm` (`packages/services/src/series-form.ts:723`), goes through the same series services, so published rows match the planner's (assumed from code; no live row checked). It is weekly-only (`adapters/series.ts:171`) and create-only: a published series is "changed in its planner" (`series-form.ts:738`); re-saving a draft archives it and makes a new id.
- Hand-picked dates: the schema allows them (`series_sessions.slot_at` is nullable, "reserved for weeks with no rule", migration 203 header). The code does not: `resolveWeek` refuses an instant that is neither a row nor a rule date (`meeting-series.ts:1342,1554,1605`); a rule-less week would read as off-schedule and never publish (`meeting-series.ts:975-999`); `findOrgSeries`, `seriesIds` and reminders require `recurrence_pattern IS NOT NULL`. The ICS export already omits the RRULE for `CUSTOM`; ifac's `/series` List and Calendar are built from session rows and would cope.

### 2.5 Offerings
- `packages/services/src/artist-offerings.ts` is artdirect's owner-drawer layer for a person's offerings in org `oad`. It has no table of its own: meetings are written to `threads` directly; services go through `upsertServiceOffering` with `authorOnly` (`artist-offerings.ts:246`). It also owns the featured offering (`users.featured_thread_id`, migration 171).
- `packages/services/src/service-offerings.ts`: `threads.kind = 'service'` plus the `workshop_pages` sidecar (migration 038 onward). No capacity or schedule on the offering; booking type is `metadata.bookingType`; one-to-one booking times in `service_bookings` (migration 174, written, not applied per `docs/reference/commerce.md`; not checked against the DB).
- The Studio Offering form refuses the personal org (`apps/arts-collective/src/lib/service-form-actions.ts:63`) and has no author-only path, so it cannot yet serve artdirect's artists.
- Field mismatches: duration in minutes (artist meetings) vs hours (`session_duration_hrs`); `excerpt` vs `descriptionShort`; visibility enums (artist maps ORGANIZATION to INVITE_ONLY); `location` in `threads.location` vs `workshop_pages.location_address`; nullable vs required price.
- elktours experiences point at a `kind = 'service'` thread (`apps/elktours/src/lib/experiences.ts:32`), so the experience-as-composite direction already has a hook.
- People see "Offering" in Studio and arts-collective; "Service" on hidden-enneagram, sunjay, elastrocal and the elktours `/services` route.

## 3. Rules and constraints
- Keep three, konva and Filerobot out of `studio-forms`: every site installs its dependencies, and sunjay's build already ran out of memory on 2026-11-11.
- A Quick-Form or Norm-Form save merges `metadata` and leaves `body_doc` alone when it did not edit them: Deep-Form keeps layout, SEO and publish options there, and a replace would erase them.
- Write `min_role` and visibility in the shared save before any inner_group site uses it: the current fallback to `'PUBLIC'` would expose members-only meetings.
- Settle the kind id (`meeting`) before the package is cut: every site's wrapper and link will carry it.
- Move no forms files until the forms-body session has agreed: it owns the fields, kinds, sections and theme (`HANDOVER_TEAM_2026-11-14.md` §1).
