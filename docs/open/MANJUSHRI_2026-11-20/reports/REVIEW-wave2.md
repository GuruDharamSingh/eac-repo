## Findings

### Important

1. **`read_page` returns hidden blocks inside legacy `zones` unredacted.** `packages/mcp/src/server/site-read.ts:134` (`redactHidden` returns `{ ...doc, content: fix(doc.content) }`; `zones` is copied as is), and `walkBlocks`/`outlineOf` only walk `content`. Scenario: a page still in Puck's old zone format holds a `contact-form` (or `he-contact`) in `zones["x:y"]`; `read_page` hands its props (recipient address in `note`/`intro` text, topics) back inside `document.zones`, fenced by `plain()` but not hidden. Same for any hidden block nested in a non-slot structure (an array item that holds a slot). Fix: in `redactHidden` drop `zones` (or run `fix` over each zone's list) and add `zones` handling to the unit test; simplest is `const { zones: _z, ...rest } = doc; return { ...rest, content: fix(rest.content) }` and say "legacy layout, not shown".

2. **The deny list fails open on blocks whose declaration the scan could not read.** `packages/mcp/src/manifest/deny.ts:56` (`denyReason` looks only at the settings it was given). Three Katie blocks carry a setting named `?` of kind `unresolved` (`ktp-artwork-grid`, `ktp-piece`, `ktp-piece-row`): the static scan hit a spread it could not expand, so settings may be missing from the manifest that would have tripped the word list (email, token, key, ...). They are readable and writable today. Fix: in `denyReason`, deny any block with a setting of kind `unresolved` (new code `unresolved`), until someone reads those three files. Same reasoning for the 9 no-declaration blocks (already denied, correct).

3. **Structure steps in the Sites tab ignore slot allow lists of app-local blocks.** `apps/development/src/lib/sites-contracts.ts:48` builds `rules` only from blocks this server can import; `apps/katie-the-potter/src/blocks/piece-row.tsx:16` (`allow: ["ktp-piece"]`) and `quick-landing.tsx:48` (`allow: ["ktp-piece"]`) are in neither the manifest nor the rules, so `stepConfigOf` gives those slots no `allow`. Scenario: Blocks hand, insert a `pt-banner` (or move any block) into `ktp-piece-row.pieces`: the door accepts it and the draft can be published; the live row now holds a block Katie's own editor would have refused. Contract (WAVE2 DEV item 2: "slot rules honoured") not met for 3 slots (check says "no shared block declares an allow list", which is true only of shared ones). Fix: carry `allow`/`disallow` per slot in the manifest (`blocks.json` has the source; `build.ts` `slots` is names only), feed it to `stepConfigOf`; stopgap: add a hand-written `rules` entry for the two Katie slots.

4. **"The look wins" is false for most properties.** `packages/direct-edit/src/panel/where.ts:135`. `blkStyle` is drawn as inline style on a `div.blk-st` wrapper (`packages/page-builder/src/style/wrap.tsx:25`) around the block; the look is an `!important` rule on the root element inside it (`morph.ts` `rule()`). Different elements, so only inherited properties (text colour, font) are decided by the look. Margin and padding add (wrapper's plus root's), opacity multiplies, border and box-shadow both draw (nested), width/max-width compound, background shows from the wrapper wherever the root's is transparent. Scenario: Style padding 40, look padding 10: the block has 50 of space, and the panel says "The look wins." Fix: wording by property: for `PROP_WORDS` entries that are text colour only say "The look wins."; otherwise "Both apply, one inside the other." (or one neutral sentence: "Style and this look both set X. Both apply.").

5. **The When/Screen choice lives in a closure that Puck can throw away (unverified, likely).** `packages/direct-edit/src/puck/look-panel.ts:195` (`let where`, `new Forcer()` per `mountLookPanel`). `InjectedPanel` (`packages/page-builder/src/parts/panel.tsx:207-215`) destroys and remounts the panel whenever `mount` changes, and the same file's comment at `look-panel.ts:183-188` says Puck remounts the fields column when a block's props change (that is why `openTab` is module level). A look edit is a props change. Scenario: choose On hover, type Size 80 (written to `states.hover`); if Puck remounts, `where` is `{}` again and the next field typed is written to the BASE look, and the forced hover mark is dropped; the person believes they are still editing hover. The browser run (`drive-where.cjs`) edits once then switches back; it does not type twice. Fix: keep `where` in a module `Map` keyed `${ctx.id}~p:${ctx.part}` like `openTab`. (The canvas panel keeps it in `tree-editor.ts:252-255` per selection and is fine.)

6. **An assistant's save can replace a person's draft that landed in the window.** `packages/mcp/src/server/draft-tools.ts:185` (load) to `:225` (save): `saveDraft` is an unconditional upsert (`packages/page-builder/src/drafts.ts:166`). The check "a person's draft is never replaced" runs on the draft read at the start; a person saving a draft (or a first draft) between the read and the save is overwritten, relabelled as the assistant's. Window is the door run plus a round trip (milliseconds), 30 proposals a minute. Fix: re-`loadDraft` immediately before `saveDraft` and refuse if `savedAt`/`author` changed; closing it needs a compare-and-set (`WHERE value->>'savedAt' = $expected`) in `saveDraft`. The Sites tab's `saveSiteDraft` (`sites-actions.ts:75`) has the same read-then-upsert (wave 1 Minor, still open).

### Minor

- `packages/mcp/src/server/draft-tools.ts:107-108`: `scan` stops at depth 40 and at 400 siblings, so a block past either limit is not in `allowed`. A step aimed at a hidden block there is not stopped by the scan; the door still refuses it (`unknown_type`) but with the message `The block type "<type>" is not in this site's catalogue.`, which names a hidden block's type. Fix: in `scan`, set a `tooDeep`/`overflow` flag and refuse the whole proposal when a list is cut.
- `packages/mcp/src/server/draft-tools.ts` `resultsOf`: a key with ONLY `mcp:draft` (no `mcp:read`) can use the door's answers as a read oracle: `code: "same"` ("already says that") tells whether a guessed value equals the stored one; `unknown_prop` lists a block's setting names; `waitingFrom` tells a draft exists. Visible blocks only, guesses only. Fix: require both scopes to propose, or document that `mcp:draft` implies read of visible blocks.
- `packages/mcp/src/server/audit.ts:30,40`: the audit row keeps `input` only up to 4000 characters, else `{omitted}`. For a write tool that means a 20 KiB proposal leaves an audit row with no record of what was asked. The draft itself holds the steps (up to 64 KiB), so it is recoverable until discarded. Fix: for draft tools store a hash and the step count, or raise the cap for them.
- `packages/mcp/src/server/site-read.ts:19,25`: `SAFE_KEY` (49 chars) and `SAFE_NAME` (100, allows `:./-`) let a hyphenated or underscored sentence through as a key, an `id` or a `type` value outside the fence (`Ignore-previous-instructions-and-...`). Much narrower than wave 1's hole (no spaces, no punctuation). Fix: cap keys at 24 chars or require them to be declared prop names of the block.
- `apps/development/src/lib/sites-pages-core.ts:41-43`: "New page" checks that no live page or draft exists, then upserts (`saveDraft`): two admins naming the same page at once, the second overwrites the first's blank draft. Harmless (a blank draft) but the stated rule is "cannot overwrite".
- `packages/house-editor/src/fields/blocks.ts:94`: when the screen sends no `version`, only the store's read-to-write guard runs (against the version read a moment earlier), so a screen that opened long ago can save over a changed page. The lens always sends one; the server does not require it. Fix: refuse a save without `version` for block fields.
- `apps/development/src/components/sites/DraftReview.tsx` (`compare`, `stepWords`): a `set_look` step shows as "Change the look of ..." and the diff as "Look: its look to changed", never the values (hide, size, a hover colour). A reviewing person publishes a look they cannot read unless the before/after drawing shows it (a hover look does not). Fix: list the changed keys of the look (names and values) per part and state.
- `apps/development/src/lib/sites-manifest.ts:55`: token type is guessed from the name (`size|width|height|...` is a length, else a colour). A colour called `--x-sizing-ink` would be typed as a length; harmless (still hex-or-length only, fonts refused), just a wrong rule.
- `apps/development/src/lib/sites-pages-actions.ts`: `/pages` writes the live page while a draft waits for it, which makes that draft stale (DraftReview says so). Fine as designed; mention in the UI next to "Edit page".
- Settings with `format: "color"` are kind `string` in the manifest, so the door accepts any 400 characters for them. Katie's blocks hex-check at render (`about-hero.tsx:99`); I did not check `pt-banner` (`scrimColor`, `inkColor`, `accentColor`), `section-banner.accent`, `picture-wall.captionColor`, `dm-collection-nav.labelColor`. Fix: carry `format` into the manifest and have the door check hex for `color`.

## What I checked and found clean

**1. Assistant draft tools.**
- Scope: `propose_page_patch` and `set_field` are registered only through `draftTool`; `registerChecked` (`tools.ts`) tests `grant.scopes.includes('mcp:draft')` before the limiter and before `fn`, so a read-only key never reaches `propose` through either tool, `set_field` included. Both audited as `auth`.
- Org: the org is `settleOrg(grant, args.org, true)` only; every call after that (`loadPageWithVersion`, `loadDraft`, `saveDraft`) takes that id. `set_field` takes the page from the field id and the org from the grant; nothing from the id reaches an org. Unbound keys reach owner/guide orgs only, a bound key refuses another org.
- Live row: the only writer reachable is `saveDraft` (key `puck-draft:<slug>`); `McpDrafts` has no publish; `mcp-drafts.ts` wires exactly three functions. A page that does not exist is refused, so no new page.
- Step list: array check, 1-50 steps and 32 KiB before anything else; the body is already capped at 64 KiB by the handler. `ALLOWED` is `hasOwn`-tested, so `constructor`/`__proto__` as `op` fail; extra keys refuse the list; `block`, `prop`, `part` pass name regexes; reserved look/editor props are refused by the door (`LOOK_PROPS` includes `blkStyle`, `EDITOR_PROPS` has id/puck/editMode/children). `set_token`, insert, move, duplicate, remove are refused before the page is read. `state` and `at` are validated by the door.
- Hidden blocks: `scan` marks a block `ok` only when its type is visible and no ancestor is hidden, ANDs duplicate ids, and refuses with one fixed sentence that names no type, setting or value. After the door runs, `frozen` (hidden top-most blocks, exact JSON) and the block count must be unchanged. The contracts the door gets hold visible blocks only, so even a miss in the scan ends in `unknown_type` (see the Minor above for the one case that names a type).
- Stored data: the draft goes through `saveDraft` (`sanitizeRichValues`, `validatePage`, 512 KB); text settings are not tag-stripped, exactly as a person's save; rich text, rows, custom and slot settings are not writable by the door. At publish, `publishSiteDraft` runs `cleanBoxDoc(stripResolvedKeys(...))` and `sanitizeRichValues` again. Note and label go through `plain()` (500 / 120). Steps are stored as sent, shape-checked, rendered as cut plain text by `DraftReview` (React text, no HTML sink: grep found no `dangerouslySetInnerHTML` in the development app's sites code).
- Fencing, 166 readable blocks: `fenceDocument` walks every value (nested slots, rows, arrays at any depth to 40, rich text strings), caps 1000 chars each and 200 000 per document, drops keys that are not `SAFE_KEY`; `walkBlocks` builds paths from safe keys only; `outlineOf` lists a hidden block as `hidden`; `untrusted` lists `blocks[*].id/path/type`. Gap: zones (Important 1) and the hyphenated-name residue (Minor).
- Audit: every call that reaches the tool writes one row on every branch (scope refusal, rate limit, thrown error, refusal, success); audited org is the settled one. Calls rejected by the JSON schema before the tool (documented) write none.
- Rate limits: one `Limiter` per handler process, 120 requests, 60 calls, plus 30 writes a minute per grant, all keyed by grant id.
- Route hunk: two additive lines (`pages`, `drafts`). `mcp-drafts.ts` imports the door by relative path; same build question as apps/development (see below).
- The widened rule is computed in one place: `agentOf` in `build.ts` asks `denyReason`; `visibleBlock` is the one reader; `describe_block` and `list_blocks` honour it; blocks missing from the manifest read as hidden (fail closed). `box` has only a slot and a tag select (no CSS/HTML field).

**2. Sites tab and the development org.**
- Gate: `saveSiteDraft`, `publishSiteDraft`, `discardSiteDraft`, `createPageAction`, `pagesFieldsLoad`, `pagesFieldsSave` each call `adminOrThrow()` first (the check script asserts it), the actor is `admin.userId` from the session, the three "use server" modules export only async functions. `listSites`/`loadSitePage` gate themselves; `listSitesFrom`, `createDraftPage`, `sites-config`, `sites-manifest` are not "use server" and no client component imports them (client files import `sites-door`, `sites-doc`, `draw`, and the action modules only).
- Org and slug: `orgExists` (id only, 100 chars) and `isValidPagePath` before any key is built. `/pages` actions: `DEV_ORG` is a module constant in `saveLive`, `blockFields` and `createDraftPage` call; the client sends only `{kind, id, values, version}` and the page slug inside the block id is validated by the loader and by `slugProblem`. A block id of another page can only name a page of the development org that already exists.
- Publish: refused for legacy `zones` (`hasLegacyZones`) and for any type in no manifest (`unknownTypesOn`, which walks nested arrays more loosely than the door), always through `publishDraft` with its `base` guard and a `clean`; a stale draft or basis is refused and kept. `/pages` saves with the version passed to the store (no `storeGuard: false` anywhere in the repo).
- Contracts: the manifest contract is stricter or equal everywhere I could compare it: a select with no options refuses every value; kinds `rows`, `richtext`, `custom`, `slot`, `unresolved` are refused; `binds` carried; look and editor names refused first by the door; tokens accept hex colours and short lengths only, fonts never. Where the app can import the block its real declaration wins.
- No raw HTML sink; `forDrawing` never mutates the stored document. A new page: draft first (`base: null`), existing page or draft refused, slug from `slugOfTitle` then `isValidPagePath`.

**3. Look panel.**
- Defaults: `editLookAt` with `{}` = clone, edit, `setPartLookAt({})`, which for a look without `states`/`at` stores the same object `setPartLook` stored; the 20 v1 golden fixtures are byte-identical for public and editor CSS and a check proves the public CSS never names `data-de-force` / `data-de-at`. History: writes go through `ctx.live`/`ctx.commit` as before. The popup's "Use on this page" hands the part back whole.
- Public pages: `morphCss(..., { editor })` takes `editing` from Puck's `isEditing` (`morph-mark.tsx:32`); the forcing selectors exist only in that branch, and the attributes exist only on elements the editor marks. A public page cannot reach them.
- Switching: `where` is cleaned (`cleanWhere`), a state and a size cannot coexist, Always on Phones stays on Phones; the canvas panel keeps `lookWhere` per selection. The canvas path writes at `whereNow()` and resets on a new selection. (Remount concern: Important 5.)
- `hide` writes the base look only (state cannot hide), eye and free move unchanged. The `box-panel.ts` and `mount.ts` `freeMove` hunks belong to the free-move worker; not reviewed here.

**4. Live field editing.**
- Server decides: each site's `FieldsLensGate` renders `null` unless `viewer.canEdit`; draw sites pick `markedPuckConfig` and the `<template data-blk-page>` only for `viewer?.canEdit`; a visitor gets `serverPuckConfig` (same markup as before).
- Saves: `createSiteFields` -> `createBlockFields` -> the app's `savePageAction` (`createSavePageAction`: `getApiEditor` gate, slug rules, resolver keys stripped) with the version read just before; `storeGuard` is not set anywhere. The lens `authorize()` runs first on every load/save. `record:thread:` fields go through `threadRoute` (org-bound read, `readOnly` enforced on the server); no site passes `performAction`, so every thread is read only; nothing writes `threads`.
- No internal id reaches a visitor: the block map and thread ids go only into the editor-only HTML and the client lens props, behind the gate.
- The layouts already called `getViewer()`; the gate adds one more per request.
