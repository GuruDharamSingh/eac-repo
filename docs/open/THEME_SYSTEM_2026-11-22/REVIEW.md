## 4. How many variables, and what they are called

innergathering's Site style exposes **148 editable variables**: 14 in the schema itself, 46 in `site-style-ig-vars.ts` (41 palette colours and 5 font variables), 88 translucent colours in `site-style-ig-alpha.ts`. The static parse (themes.json, `apps.innergathering.families`) finds 287 variable names read or set in the app: ig 140, shadcn 37, eac 35, tailwind colours 22, plain colour names 12, eac-surface 9.

Two spellings coexist: shadcn bare names holding "hue sat% light%" triplets, and generated `--ig-*` names that say what the colour is or embed its hex. Fifteen real examples:

`--background` (42 60% 96%), `--foreground`, `--primary` (226 97% 24%, labelled "Navy (main accent)"), `--gold` (42 40% 53%), `--smoke` (deep navy), `--site-font-heading`, `--ig-c-navy-deep` (#01124e, used 62 times), `--ig-c-gold` (#b79a55), `--ig-c-paper` (#fffdf8), `--ig-c-slate-3` (#2c3d61, used once), `--ig-c-x-f6efe2` (auto-named "Shade #f6efe2"), `--ig-a-01124e-06` (navy at 6%), `--ig-a-b79a55-45` (gold at 45%, 9 uses), `--ig-a-063179-94`, `--ig-font-display` ("Brothers" over "Venture").

Pattern: names say what a colour IS (navy, gold, slate-3) or its hex, not what it DOES. No role names exist on this site. The roles a role system needs (ground, ink, accent) are present as `--background`, `--foreground`, `--primary`/`--gold`.

amrit-canada: 140 variables in themes.json (shadcn 39, eac 26, tailwind colours 20, eac-block 12, pc 9, eac-surface 8, sf 7, feed 6, wr 5). The palette is shadcn HSL triplets in `globals.css` plus hand-written bridges to `--eac-control-*` and `--eac-block-*` (about lines 71-110, each like `hsl(var(--background))`). Its focus ink is pinned to a literal `#8a6d16` on purpose (file comment: 4.54:1 contrast). No editor; no `site_themes` read (grep of `apps/amrit-canada/src` for `site_themes`, `getThemeOverrides`, `resolveTheme`: no hits). theme-language.md:195 says it "is being left behind: do not let its shape become canonical".

## 5. What a 5-colour, role-based site would need, and what already helps

Needs:
1. A decision on which 5 roles (section 7). L's core 12 is a superset; the 5 seeds might be ground, ink, accent, accent-2 and one more.
2. A derivation step from 5 seeds to the rest: soft panels, quiet text, lines, accent-ink, on-accent, hover wash, translucent tints. Today each is a separate stored value (innergathering has 88 translucent ones).
3. Somewhere to store the 5 values: new keys in `site_themes.vars` fit today (untyped jsonb; the sanitiser checks only the name pattern `^--[a-z0-9-]{1,60}$`, per ramps.ts:90), or L's v2 shape (not built).
4. Roles mapped to what sites read: `--background`/`--primary` triplets (needs hex-to-hsl, which exists at style.ts:250), innergathering's `--ig-*` families (not role-driven; the ~100 translucents would become `color-mix` of a role, theme-language.md:176, 191), and blocks, surfaces and forms. D's plan is the role as LAST fallback in each of the four CSS families (design-system.md:77, 151). Not done.
5. Retire or re-route the nine hard-coded `.blk-frame[data-palette]` palettes and the literal fallbacks in blocks.css.
6. `cleanVar` accepts only hsl, hex, rgba, length, font, background, choice (style.ts:127-139): derived values are fine as hex; `oklch()` and `color-mix()` are rejected in stored values by design.

Already supports it:
- `deriveRoleRamps`: accent, accent-2, neutral at 100..900 in OKLCH, mirrored on dark grounds, `-on` and `-ink` chosen for contrast. Output is plain hex so it can be stored. Hub cards and forms already read these `--eac-accent-100..900` names as a fallback level (ramps.ts header, lines 1-8).
- `color.ts`: OKLCH/OKLab conversion, `mix`, `mute`, `lighten`, `contrast`, `luminance`.
- Site style editor: contrast pairs (`on`), a fold for "More colours", live preview, `applies` selectors for sites whose CSS uses literals.
- `hslToHex` / `hexToHsl` (style.ts:240-262).
- Values land on `html:root`, so they beat each site's own `:root` and `.dark` (style.ts:198-206).
- `/themes` in the Development app already previews a site's real blocks under a draft theme, so a 5-colour model can be tried without touching live sites.
- `@elkdonis/tokens` imports a DTCG file into the same flat bag.

## 6. Conflicts and duplications

1. **Two proposals for the same role list.** D has about 24 roles and kinds; L has 36 and drops kinds as roles (decision 10). L reversed D on `--card` (theme-language.md:91). D applies `--eac-*` as fallbacks inside four CSS families; L adds `defineTheme` and stored v2 keys. Two routes to one idea; neither built.
2. **Tints: `accent-soft` (L, proposal) versus `--eac-accent-100..900` (gradients, built).** Same job, different names and method (a stored "hover wash" versus a derived ramp). Spelling clash: L `on-accent` and `accent-ink`; built `--eac-accent-on` and `--eac-accent-ink` (ramps.ts:96-97). `--eac-accent-2` is already a ramp prefix.
3. **The `--eac-` prefix is already in use with other meanings**: `packages/ui/src/eac-theme.css` (`--eac-bg`, `--eac-panel` = a translucent cream, `--eac-bg-warm`) and innergathering's own `--eac-ink`, `--eac-ink-muted`, `--eac-accent` (L's innergathering table), set to `var(--ig-c-navy-deep)` and so on. In L, `--eac-panel` would mean "Cards and panels".
4. **Colour format.** L picks hex (decision 1). Site style stores shadcn triplets for shadcn names, hex for `--ig-c-*`, rgba for `--ig-a-*`: innergathering mixes all three. OKLCH is what the ramp code computes in.
5. **Several stores for theme values**: `site_themes` (six Site-style apps plus ifac), `site_config theme:palette/fonts` (danamccool), `users.theme`, hub skin, and amrit-canada's source file. HOUSE_EDITOR_ONE H5 (PLAN.md:129-135) and theme-language section 4 both say "one `site_themes` with a scope ladder"; neither is built.
6. **innergathering's defaults exist twice** (globals.css `:root` and schema defaults in TS), kept in step by a script. Also `HOUSE_EDITOR_ONE_2026-11-20/PLAN.md:36` still says innergathering has no Site style; code shows it does (`layout.tsx`, `lib/site-style*.ts`). Treat that table as stale.
7. **Justin's "triad of accents" versus L's accent plus accent-2.**
8. **Words:** Justin's Theme / Page-theme / Block-theme / Norm / Preset versus L's theme / look / preset (L says "look" is one element's style). HOUSE_EDITOR_ONE item F (PLAN.md:242) tries to use both. "Preset" already also means the `.blk-frame[data-palette]` palettes and hidden-enneagram's `--he-look`.
9. **Block palettes versus theme**: nine named palettes in blocks.css (lines 521-559) are a separate colour system inside the block library that no theme reaches.
